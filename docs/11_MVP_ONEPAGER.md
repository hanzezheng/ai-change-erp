# AI 农批经营助手 · MVP 一页纸

**定位：** 正经经营账本上的手机入口；AI 是少点少输，不是产品本身。

**对标菜小秘：** 只拆「每天经营动作」，不拆生态/硬件/金融。

**底线：** 无 AI 也能开单收款；无 LLM 则提示手动，不假装理解。

**优势分层：**  
1）账真、手动能用 → 2）LLM 少输 → 3）租户私有身份记忆越用越准。  
记忆是差异化内核，不是门口招牌；对外不叫「AI 记忆」。

---

## 1. 要做（传统入口，必须完整）


| 模块  | 能力                        | 完成标准                  |
| --- | ------------------------- | --------------------- |
| 订单  | 多商品开单 / 改单 / 草稿 / 提交 / 查单 | 进 ERPNext Sales Order |
| 客户  | 选择、搜索、详情（应收/最近单）          | 正式 customerId         |
| 商品  | 规格/Variant、合法 UOM、参考价     | 正式 itemCode           |
| 收款  | 记收款、分次收、补尾款、累计已收          | 与订单支付状态分离             |
| 库存  | 搜索与查看结存                   | 只读事实来自 ERP            |
| 价格  | 历史成交价（客户+商品+UOM）          | 不作假全局价                |
| 账号  | 登录、租户                     | SaaS 边界清晰             |


---

## 2. AI 只增加这些（叠在上面，不新开世界）


| 意图                          | 老板怎么说（例）       | 结果          |
| --------------------------- | -------------- | ----------- |
| 开单 `create_order`           | 老韩80果20箱，粉蕉30件 | 预填订单草稿      |
| 改当前单 `update_current_order` | 苹果改30箱；再加10件粉蕉 | 改当前草稿，不新建   |
| 记收款 `record_payment`        | 老韩收了1000       | 预填收款草稿      |
| 查客户 `query_customer`        | 老韩还欠多少         | 跳转/展示客户经营信息 |
| 查库存 `query_inventory`       | 80果还有多少        | 展示库存        |


**AI 硬规则：**

- 只出可编辑草稿 → 人点保存/提交
- 歧义只问一处，不清空整单
- LLM 不可用 → 明确提示改用手动，不做启发式假装理解

---

## 3. 明确不做（MVP 钉子）

- 催款服务 / 非诉调解
- 买家通 / 货主通小程序生态
- 代销 / 货主批次结算
- 赊欠限额账期风控产品化
- 蓝牙秤 / 标签机等硬件全家桶
- 线上小店 / 获客撮合
- 筐子管理、班次统计等长尾
- 20+ 经营大报表中心
- 图片识单 / 微信粘贴作为主路径
- AI 独立聊天 Tab / AI 工作台 / 「AI 记忆中心」
- 跨租户学习、向量库当身份主库必须做到
- 自建第二套 ERP 账本

---

## 4. 90 天顺序

1. **手动闭环天天能用**（§1）
2. **LLM 开单 + 改当前单**（有 Key 才算 AI 落地）
3. **AI 收款 / 查客户 / 查库存**
4. **商户身份记忆五类落地**（§7）→ 再考虑 OCR / 打印等后做项

---

## 5. 一句话验收

> 老板不用 AI，能在手机上把「客户—开单—收款—查库存」做完；  
> 用 AI，同一件事少输几步，且单子仍是正式 ERP 单据；  
> 越用越懂「怎么叫人、怎么叫货、习惯价和单位」。

## 6. 后做项（有客户喊再开）


| 能力               | 条件                                  |
| ---------------- | ----------------------------------- |
| 来货 / 盘点 / 报损     | 手动销售稳定后，走 ERP 流程                    |
| 一客一价             | ERP Price List / Pricing Rule 可干净接入 |
| 小票打印             | 首客有明确打印场景                           |
| OCR / 微信消息开单     | LLM 文本开单已准                          |
| 轻量赊欠展示（仅展示，不催收）  | 客户强需求                               |
| ASR 错字变体库、整单再来一单 | 有真实纠错量 / 强需求                        |

## 7. 商户身份记忆定稿（对内 Identity，对外不叫记忆）

**纪律一句话：**  
只记忆「称呼→正式身份」和「习惯→默认价/单位/常买」；不记忆聊天，不跨户学习，不替老板建第二套主数据。

**对老板展示：** 常用称呼、商品简称、最近价、常买。  
**存储原则：** 租户私有；结构化身份优先 SQL；不上向量库当主路径。

### 7.1 必记五类（按商户价值排序）


| #   | 记什么                     | 商户体感       | 怎么长出来              |
| --- | ----------------------- | ---------- | ------------------ |
| 1   | 客户常用称呼（老韩→韩兆亮）          | 说人话就能找到人   | 开单选客户，或纠正「不是这个韩」   |
| 2   | 商品简称/规格说法（八零→APPLE-80）  | 说行话就落到正确规格 | 选了 Variant，或纠正规格歧义 |
| 3   | 历史成交价（客户+itemCode+UOM）  | 少填价、少填错    | 已提交订单自然沉淀          |
| 4   | 该客户常买商品                 | 开单少翻目录     | 已提交订单统计            |
| 5   | 该 Variant 常用 UOM（箱/斤习惯） | 少切单位、少错价   | 该客户/商品历史行频次        |


### 7.2 明确先不记

- 聊天式对话历史当记忆中心
- 跨租户学习
- 向量「语义随便搜」当身份主库
- AI 自动新建客户/商品（只映射已有 ERP 身份）
- 复杂人格/偏好画像

### 7.3 记忆是否帮到忙（验收）

同一租户用两周后应出现：

1. 「老韩」稳定落到韩兆亮（或只问一次歧义）
2. 「八零」稳定落到 APPLE-80，不瞎猜 70/75/85
3. 选客户后开单 → 常买与上次价先顶上
4. 切 UOM → 价跟着变，不留错价
